### A｜OpenAI Fast mode 支持 GPT-5.6 系列长上下文请求

OpenAI 8 月 5 日 API 更新日志显示，GPT-5.6 Sol、Terra 和 Luna 的 Fast mode 已支持超过 272K tokens 的长上下文请求，官方标注速度最高可达 Standard 层的 2.5 倍。

- 为什么重要：长文档、长会话和大型代码库任务不再必须在上下文长度与低延迟之间二选一，但速度收益伴随 Fast 层定价，需要按完整任务成本评估。
- 建议行动：用同一批 300K+ token 文档与代码任务对比 Standard/Fast 的首 token、总耗时、输出一致性与总成本。
- Boards：AI Product / Model Launch；AI Agent；AI Coding；Market / Business Model
- 核验：[OpenAI API changelog](https://platform.openai.com/docs/changelog) · 内部发现源 discovery

### A｜OpenAI 发布 Codex CLI 0.146.1 安全修复

OpenAI 官方 GitHub 于 8 月 5 日 15:55 UTC 发布 `rust-v0.146.1`，为具备网络能力的模型采用更安全的 automatic-review 默认值，并在终端中解释权限变化；这是从 0.146 主线回移的安全修复。

### A｜Anthropic 推出 Claude Enterprise Inference Hooks

Anthropic 于 8 月 5 日上线 Inference Hooks beta。Claude Enterprise 可把每个 prompt、上下文与工具返回通过签名 WebSocket 送往企业自有安全服务器，由 DLP 返回 allow/deny 后才继续推理；覆盖 Chat、Claude Code、Cowork、MCP、skills 与 plugins。

- 为什么重要：企业不必为每个 Claude 界面分别接入安全代理，而能在模型看到数据之前使用统一的内联执行点阻止敏感信息外流。

### A｜Figma 实测 Code Connect 可降低编码 Agent 成本并提升质量

Figma 8 月 5 日公布 Code Connect in MCP 的内部评测：相对无 Code Connect 的基线，使用 `get_design_context` 的任务中位耗时下降 19.6%，中位 token 使用下降 29.5%，代码质量从 1—4 分量表的 2 分提高到 3 分。收益与设计系统组件覆盖率和 Code Connect 映射覆盖率强相关。

- 为什么重要：它给出了“设计上下文是否值得工程化”的量化证据，说明编码 Agent 的效率上限取决于生产组件映射，而不只是模型能力。
- 建议行动：挑选一个真实页面做有/无 Code Connect 对照实验，记录任务时长、token、组件复用率、人工返工和视觉回归结果。
- Boards：AI Coding；Workflow / Tutorial / Usage Tips；AI Agent
- 工程候选：`figma/code-connect`（verified）
- 核验：[Figma official research](https://www.figma.com/blog/the-benefits-of-code-connect-in-mcp/) · [official repository](https://github.com/figma/code-connect) · 内部发现源 discovery

### B｜Google 解释 MCP 无状态核心的生产级扩展路径

Google 8 月 5 日工程文章说明，2026-07-28 MCP 规范候选版移除传输层会话管理，使 MCP 可使用标准 HTTP 路由、负载均衡和水平扩展；Google 与 Hugging Face 等共同组建 Transports Working Group 推进这项变化。规范发布发生在 7 月 28 日，本次只把 8 月 5 日的新增工程指南记为今日事件。

- 为什么重要：MCP 从本地单客户端工具协议进入多租户云端基础设施时，状态固定和会话粘滞是核心扩展瓶颈；这篇指南提供了明确的迁移理由与架构边界。
