## 入选事件

### A｜OpenAI 公开 GPT-Live 全双工语音架构与低延迟工程路径

OpenAI 的 8 月 3 日工程拆解显示，GPT-Live 可同时监听与说话，并通过异步委派 GPT-5.5、上下文压缩、无缝实例交接和 WebRTC 维持长会话。文章称从 Python asyncio 转向 Go 后，新的 p95 流畅度达到旧系统 p50 水平。它还介绍了 WARP 与 Instant Connect：IETF 草案本身描述 6→2 RTT，OpenAI 文章描述两者组合后的单包启动路径，两项口径不应混用。

- 为什么重要：实时 Agent 的护城河正在转向状态、网络、调度和可观测性。
- 建议行动：按首包延迟、打断恢复、长会话压缩、实例交接和 p95 流畅度建立压测；跟踪 `fippo/warp-snap-sped` 与 `pion/webrtc`。
- Boards：AI Product / Model Launch；AI Agent；Workflow / Tutorial / Usage Tips
- 核验：[OpenAI engineering post](https://openai.com/index/continuous-voice-interaction-with-gpt-live) · [IETF WARP draft](https://datatracker.ietf.org/doc/draft-uberti-tsvwg-warp/) · [sample repo](https://github.com/fippo/warp-snap-sped) · [Pion WebRTC](https://github.com/pion/webrtc)

### A｜阿里云正式上线 Qwen3.8-Max API，开放权重仍待后续发布

阿里云已在 Model Studio 上线 `qwen3.8-max`，披露 2.4T 总参数、95B 激活参数、最高 1M token 上下文，并提供 OpenAI、Anthropic 与 DashScope 兼容接口。官方预告开放权重将在随后一周发布，所以今天确认的是正式发布和 API 可用，不能提前写成“权重已开放”。

- 为什么重要：超长上下文旗舰模型已能进入代码库、长文档和多轮 Agent 的真实基准。
- 建议行动：先测 API 的质量、延迟和成本；权重、许可证与工程仓库出现后再单独复核。
- Boards：AI Product / Model Launch；AI Agent；AI Coding；Market / Business Model
- 核验：[Alibaba Cloud press release](https://www.alibabacloud.com/press-room/alibaba-unveils-qwen3-8-max) · [Model Studio docs](https://help.aliyun.com/en/model-studio/models) · [Qwen release post](https://qwen.ai/blog?id=qwen3.8) · [official announcement](https://x.com/Alibaba_Qwen/status/2084100707423289643)

### A｜MiniMax H3 发布开放权重并获 ComfyUI Day-0 工作流支持

MiniMax H3 模型资产和 ComfyUI Day-0 支持同步上线，可接收文本、图像、视频和音频输入并生成带立体声音频的视频。ComfyUI 提供文生视频、图生视频和参考视频工作流。模型卡采用 MiniMax H3 Community License Agreement，因此准确表述是“开放权重”，不是不加限定的“开源”。

- 为什么重要：模型发布当天即可进入节点式本地制作和复现管线。
- 建议行动：用三套官方工作流记录显存、耗时、音画同步和失败率；商用前审阅许可证。
- Boards：AI Product / Model Launch；AI 3D / World Models；Workflow / Tutorial / Usage Tips
- 核验：[ComfyUI post](https://blog.comfy.org/p/minimax-h3-day-0-support-in-comfyui) · [official model card](https://huggingface.co/MiniMaxAI/MiniMax-H3) · [Comfy model card](https://huggingface.co/Comfy-Org/MiniMax-H3) · [ComfyUI](https://github.com/Comfy-Org/ComfyUI) · [workflow templates](https://github.com/Comfy-Org/workflow_templates)

### B｜Google 给出实时 AI Agent 的会话感知负载均衡方案

Google Developers 指出，QPS 或 CPU 无法充分描述长连接 WebSocket/gRPC 会话，建议在应用层跟踪活跃会话并与 CPU 等指标组合调度，同时处理异常断连造成的幽灵会话计数。

- 为什么重要：长连接、会话状态不均和计数漂移是实时 Agent 从演示走向生产的常见瓶颈。
- 建议行动：增加 `active_sessions`、`session_age`、`disconnect_cleanup` 与 per-instance CPU 指标，用租约或超时回收异常会话。
- Boards：AI Agent；AI Coding；Workflow / Tutorial / Usage Tips
- 核验：[Google Developers guide](https://developers.googleblog.com/scaling-real-time-ai-agents-with-session-aware-load-balancing/)

### A｜Cursor 上线 Google Workspace 插件，编码 Agent 可直接读写办公套件

Cursor 的 8 月 3 日更新日志上线 Google Workspace Plugins，覆盖 Gmail、Drive、Calendar、Docs、Sheets 和 Google Chat，可执行搜索、创建、编辑、发送及日程操作。官方没有给出公开实现仓库，相关 repo 候选保持 pending。

- 为什么重要：编码 Agent 的执行面扩到邮件、文件和日程，价值与误操作半径同时放大。
- 建议行动：先在测试 Workspace 中最小授权；发送、共享、删除和创建日程保留显式审批与审计日志。
- Boards：AI Agent；AI Coding；Market / Business Model
- 核验：[Cursor changelog](https://cursor.com/en/changelog?date=2026-08-03) · [official announcement](https://x.com/cursor_ai/status/2084376701539405904)
