# 建模工作流迁移验收（2026-11-04）

## 迁移目标及来源

复现此前会话建模的可重复环节：读图、选择比例假设、分批构建结构及家具、运行几何检查、查看实际2D/3D并修正、保存完整场景。原 floorplan 仓库是前端编辑器，没有找到独立自动建模 Skill。迁移依据为本地 `LOCAL-SETUP.md`、三例测试记录、构建脚本及实际编辑器操作；没有把旧脚本中的坐标提供给模型。

新界面使用 `codex-workflow-v1`。历史 `legacy-single-v1`、原三个案例、用户项目和版本均保留，正式站及兄弟CNB仓库不属于本次改动。

## 已实现环节

| 环节 | 实现及可复核记录 |
| --- | --- |
| 原图分析 | 分析空间、开口、曲线/玻璃、楼梯、柱、固定设施、重复布置与留白；保留每阶段输入输出哈希及私有产物 |
| 比例推定 | 自动读取标注锚点并由程序计算；无标注尝试可见物件尺寸先验，输出估算区间、假设与低置信度；依据不足最多追加一次专门估算，不用固定22兜底 |
| 已知尺寸校准 | 原图两点选取映射回原像素，输入毫米长度，后端重新计算；手动比例也保留，分析不会覆盖用户标定 |
| 结构重建 | 原像素JSON；显式墙中心线+厚度确定性构墙，曲线以多边形表达；楼梯及重复家具使用有界声明式规则展开 |
| 家具及设施 | 独立阶段只补可见家具/设施，禁止该阶段更改建筑、尺度及结构ID |
| 校验及修复 | 原像素只转换一次毫米，检查完整几何与编辑状态；错误反馈给数据修复阶段，候选及失败产物保留 |
| 原图对照 | 同源原图叠加，按原图/描摹图尺寸和坐标原点映射，可开关及调透明度 |
| 真实视图复核 | 浏览器实际SVG栅格图及Three.js场景图回传；3D固定1280×960并按实际几何取景，临时低墙，截图后恢复交互状态；排除原图叠加，避免用原图冒充重建 |
| 视觉修正闭环 | 原图+当前2D+当前3D交给模型复核；修正后新draftId、重截两图、再次复核，旧图不能用于新候选 |
| 持久化及审计 | 结构与视觉门禁均通过才提交版本；保存完整scene/state/尺度来源/复核结论，按调用记实际token；等截图释放worker，重启不重放付费请求 |

## 已验证的真实操作

带6000毫米标注的640×480合成图用于流程功能验收，不作为真实户型质量样本。图纸标注两端为(80,48)/(560,48)，自动解析及程序复算得到 **12.5mm/px**。浏览器实际点选两端后，可编辑原像素点位；输入6000毫米得到同一12.5mm/px。叠加层与原图坐标对齐，实际3D复核图为1280×960。

该合成图在真实指定网关中经过分析、结构、家具、一次几何修复、浏览器截图及视觉复核后提交版本1，共5次模型调用、15,567 tokens。模型执行累计24.797秒，墙钟117.955秒包含主任务离开待截图页面检查校尺的时间，不能当作自动流水线性能。此前一次调试因窄幅3D截图及数据问题被拒绝，6次调用22,202 tokens，保留为调试失败记录。

## 三图迁移测试

三张原图沿用原文件SHA-256；使用相同网关模型、推理档位、流程版本和预算。测试记录及截图保存在忽略的本地验收目录。没有向模型提供历史参考JSON或坐标。

这组使用固定历史参考尺度以单独观察结构及家具重建：住宅22mm/原图像素，办公35mm/原图像素；Tugendhat旧25mm对应1976像素描摹宽，而原图宽2000，所以换算为24.7mm/原图像素。它们均是示意假设，不是实测尺寸。自动估尺另测，不能把此组冒称自动估尺成功。

冻结profile为`workflow-v1-prompts-v3-reference-json-b12`，提示版本`codex-workflow-prompts-v3`，Responses JSON object模式开启，推理none，输出12,000，预算12/4/4。

三例原始完成率为0/3；不能以可预览的住宅候选、此前历史参考或合成图成功替代。原始18次调用共166,977 tokens。接口均返回用量，网关货币单价未确认，费用保持未知。上表“排队至结束”按实际事件时间计算；单worker会在等待截图时执行另一项目，住宅中途复核等待与办公首次排队均包含在内。API的`timings.wall`从首次worker执行开始，不包括初始排队，不能拿它冒充提交至完成耗时。

办公重复响应是适配健壮性缺口：只允许将完整且完全等同的JSON重复折叠为一份，冲突内容、不完整内容和额外文字仍拒绝；不自动取第一份、不宽松解析JavaScript对象。定点修复后的独立回归结果另列，原失败保留，不能覆写上述0/3分母。

### 办公定点复验（独立追加记录）

适配修复版本`strict-json-repeat-v1`上线本地开发版后，以相同原图、手动35mm/px、提示v3和12/4/4预算，仅追加一次office任务，profile `workflow-v1-prompts-v3-normalized-json-b12`。真实旧响应离线回放由3355字符、两份完全相同的完整对象严格折叠为1677字符；不同对象及附言回归仍拒绝。

新增任务完成分析、结构、家具与4次几何修复，共7次调用、66,089 tokens（输入43,647+输出22,442），调用累计113.791秒，提交至终态116秒，最终仍`workflow_repair_budget_exhausted`：房间索引3、7、9超出模型提供的外轮廓，未进入视觉复核，未提交项目版本。此轮各调用都是单个JSON，归一化均未实际触发，不能把这一轮当作线上重复传输复现；它证明正常响应继续兼容、流程能进入后续阶段，而不是证明几何质量已通过。

三图原始组加这次追加复验共25次调用、233,066 tokens；合成图、估尺、协议探测及其他调试另记，不混入该分组总量。当前真实三图的质量通过仍为0/3。

住宅自动比例另测profile `workflow-v1-prompts-v3-auto-json-b12`，1次调用2,613 tokens，发现门/床/餐桌先验比值不一致且估算区间不覆盖全部锚点，因此进入`needs_input`。服务没有使用22兜底。校准图自动算对12.5证明计算与完整流程可用，但无标注真实图的模型锚点定位仍需改进；失败/待补输入的原图、要求与尺度可恢复后重新校准。

## 比较边界

本轮是流程迁移验收。当前供应商模型为 `deepseek-v4-1-flash-260910`，Responses，`reasoning.effort=none`，每次输出上限12,000。验收配置固定为最多12次调用、4次共享修复及4次视觉复核，job创建时保存预算。默认产品配置仍8/2/2，非法组合拒绝。该配置与早期Codex内置模型、推理档位、工具及人工修正预算不同，旧参考与本轮结果不能作为控制变量相同的模型排名。

后续模型对照应保持同一产品流水线、原图、尺度策略、提示/编译器/renderer版本、预算及验收清单，只替换provider；记录所有失败、等待和人工修订。模型自我复核通过不等于独立人工验收，也不等于现场尺寸准确。

当前结论是主要生成与复核环节已产品化并实际贯通，真实三图尚未达到可用质量验收。固定单个3D视角存在遮挡，部分复核建议涉及相机或渲染表达，当前数据修正工具不能直接改变这些设置；后续应区分数据错误、渲染限制及证据不足，避免消耗修复预算却无法落实建议。不能据本轮结果宣布效果已与旧Codex会话一致，或归因于某一模型的绝对能力。

住宅末轮的独立只读核对进一步确认：淋浴、马桶、洗手台均存在且落在卫生间内，实际3D截图中确有墙柜遮挡；3D已有门叶和把手，但开启弧线是2D SVG表达，不能靠JSON修正产生3D弧线。与此同时，两扇门仍有门洞跨度1100mm而门叶长1320/1540mm等不一致，2D图可见错位弧线。因此保留未通过结论：先让复核区分2D开启关系、3D门叶与通行、单视角不可见，再扩充反向/局部取证与门参数约束，不能简单放宽门禁或把全失败归因于renderer。
