# AI 实验室模型验证记录

记录日期：2026-11-03。`none + pixel-scene-v2` 三图任务结果及别墅的实际浏览器 3D 复核已补齐。本轮记录整理只读取已有探测摘要和本机任务状态，没有新增模型调用。

当前结论：本地工程链已能接收图像、调用指定网关、记录任务和用量、拒绝无效几何，并保存及重新打开完整场景与编辑状态。本组三图中，别墅实际生成并保存，住宅和办公因几何错误未保存，即几何通过 **1/3**；别墅已完成实际 3D 及重开复核，渲染正常，但细节覆盖不足，仍不通过还原质量验收。这不是质量达标 1/3，也不能宣称模型还原效果与 Codex 持续协作一致。可打开的参考案例不能替代真实生成的验收。

## 验证范围与口径

- 模型：`deepseek-v4-1-flash-260910`；指定网关的 Responses 协议。文本及图像输入经过实际探测，不能只凭上游厂商文档推断网关能力。
- 完整生成测试的单次输出上限为 12,000 tokens。该上限包含可见输出与推理 tokens，不能理解为 12,000 tokens 的场景 JSON 额度。
- 原图坐标交由模型以原像素输出，再由确定性编译器按用户明确提供的假设比例转换一次；现有比例不构成测量精度承诺。
- 每个生成任务最多初次调用加一次针对校验错误的修复。模型请求完成、JSON 可解析、几何有效和视觉还原合格是不同的检查点。
- 下表“总 tokens”使用网关实际返回的 `total_tokens`；推理 tokens 是输出 tokens 的组成部分，不能再次相加。用量缺失保留未知，不计为零。没有经核验的价格，本文不估算金额。

### 首次默认配置的用量审计缺口

首次住宅任务在提供方判定响应不完整时抛出错误，早于 usage 的归一化和返回，因此数据库中的该次调用 usage 为 null。这是实现缺口，不是免费调用或零 tokens 的证据；现有记录无法据此还原实际消耗，也不能编造补值。

后端已修复：提供方错误可携带经过白名单处理的 usage、响应状态和中断原因，生成及修改任务均可保留失败调用的实际用量；离线回归覆盖输出上限中断、保留用量、不重试和不提交场景。后续 `low` 失败任务已实际保留总 tokens 与推理 tokens。该修复不追溯改变首次缺失记录。

### 住宅 `none` 轮次的几何失败

关闭思考解决了本轮输出被推理占满的问题，但没有解决场景合法性。一次针对性修复后仍有八项错误：三段墙越出图像边界；窗台与窗头高度数组长度分别与窗口数量不符；一个房间多边形出现零长度边；外边界越界；另一个房间落在外边界之外。

初次调用用量为输入 924、输出 2,512、总 3,436；修复调用为输入 3,808、输出 2,473、总 6,281。编译器没有替模型裁切坐标或放宽几何标准，失败事务没有提交新场景版本。返回了房间、墙或家具的数量，也不能据此判定还原成功。

`pixel-scene-v2` 随后强化了逐轴原像素边界、正面积矩形、多边形去重、窗口高度数组契约及可选外边界规则，并在修复消息中区分编译后 mm/mm² 诊断与原像素输出。它是提示改进，尚不能当作结果质量改进的证据。

### 别墅的细节覆盖边界

实际生成场景包含 11 个房间、19 段墙、15 件家具、1 个多边形墙构件、0 个台阶构件和 4 根柱。保留的 Codex 参考案例相应计数为 20、46、70、3、93、16。两种场景的构件拆分和分段方式不同，不能将这些数字直接除成召回率或准确率；参考也不应替换本次实际生成结果。

模型自身的 warnings 明确披露左侧楼梯被省略，以及 Wintergarten 的玻璃线被省略。这是具体的遗漏证据，与“几何校验无错误”可以同时成立。当前结论是：**细节覆盖不足，当前不能复现原 Codex 案例的细节精度**。这里指案例中的细节与还原水平，不是经尺寸真值测量得到的量化准确率。

执行任务已在浏览器打开本次实际生成、来源为 `generated` 的初版场景，完成 2D→3D→斜视切换及服务重启后重新打开，未见控制台错误。关闭房间标签后，主体和左侧服务空间可正常渲染；楼梯、冬花园玻璃等细节缺失。私有截图已留作核验依据，本文不嵌入私有图片或路径。因此此次复核确认的是“渲染与重新打开正常”，还原质量验收仍不通过。

## 工程链和产品质量的不同验收

已有工程证据包括：Responses 文本及图像探测、任务排队与轮询、取消后禁止提交、失败状态与实际 usage 留存、版本冲突检查、完整场景及编辑状态存储、导出与重新加载，以及受限家具和房间属性修改。本组别墅还验证了真实模型输出经修复、编译校验、保存、实际 3D 渲染及重启重开的链路；视觉复核同时发现其还原质量不足。参考案例载入、编辑和重开验证的是操作链；来源应持续标记为参考或已修改的参考。

这些结果不证明任意平面图都能直接生成正确空间，不证明默认或 `low` 配置能在当前预算内完成，也不证明其效果与 Codex 结合上下文、工具、视觉检查和多轮修正的工作方式一致。本组样本数量有限，完整生成尚无可计入视觉合格率的成功产物，不发布泛化成功率。

## 下一步评估方式

直接让单次模型请求生成完整遗留场景，当前同时受到推理额度和几何一致性问题制约。后续应先评估结构拆分：让模型分别输出可核查的房间/结构识别、墙与开口几何、家具及属性，再由固定契约组合并逐阶段校验。每阶段保留明确原图坐标、稳定对象 ID、尺度假设、用量和失败原因；不能通过自动夹紧坐标或削弱校验掩盖识别错误。

结构拆分仍需视觉回归证明价值。对住宅、别墅、办公分别比较原图与生成的 2D 叠加及 3D 视图，检查外轮廓、房间邻接和留白、墙与门窗、核心构件、家具尺度与位置，再验证编辑、保存和重开。预先约定关键错误和人工修正范围；几何合法、视觉可信、可编辑且重开一致后，才将该次结果计为生成成功。

在同图、同尺度假设、同检查清单和可审计调用预算下，再比较单次模型、分阶段流水线及 Codex 持续协作的输出质量和人工修正成本。没有这种对照前，结论应保持为“工程 MVP 可运行，模型还原质量仍在验证”。
