# Floorplan Studio · 展示 Demo

本轮先验证独立空间应用的工作台形态，不实现完整多应用市场。开发版入口仍为 `http://127.0.0.1:5186/#/ai-lab?tool=floorplan3d`，仅 `codex/ai-lab`，正式站由主项目决定接入和发布。

## 设计与交互

采用 `apple-design` Skill 的即时反馈、空间连续性、按需面板与减少动效原则，并通过 Codex Design MCP 完成 brief、迭代及交接检查。Floorplan Studio 使用独立的石墨、雾灰和珊瑚色系统，继承原站的其他页面不改变主题。

- 移除实验室的居中最大宽度和大标题区，使用全视口工作台；项目与生成/对话面板靠窗口两侧。
- 两侧可单独收起，专注模式为模型释放空间；窄屏采用活动抽屉。
- 内部编辑器的家具库与属性面板默认收起、按需打开，2D/3D和画布工具保持可达。
- 3D默认关闭面积标签以减少遮挡；2D标注保留。交互相机按实际网格的投影取景，避开顶部100px、底部80px的工具区；固定工作流截图的构图与1280×960协议独立保留。
- 使用真实已有案例展示，保留“历史参考”的来源标识；原图、校尺、任务原因和原有项目输入继续可访问。

## 已核对的 Three.js 能力

本地依赖为 Three.js r160。现有编辑器提供45类程序化家具，普通墙及多边形墙、柱、台阶、玻璃，灯光、软阴影、Orbit、漫游、房间取景和剖切。两种真实展示预设只改变渲染与取景，不更换户型几何或修改已保存JSON。

目前玻璃通过透明材质表达，不是完整物理透射/折射；没有现成的GLTF素材工作流，也没有对全部重复构件做实例化与批处理。更丰富的家具款式、真实材质和缺失结构需要另做资产或几何工作。UI与灯光改版不提高图像识别准确率。

办公案例包含大量程序家具与构件，细分mesh、透明材质、阴影及高DPR会增加渲染成本；首轮未做独立GPU/FPS性能基准，不给帧率承诺。以单个viewer加载当前案例，复杂案例按需打开。

## 验收边界

本轮不调用模型重新生成、不改既有户型数据，不将示例参考改标为AI新生成。以真实浏览器核对全宽画布、两侧展开/折叠、家具/属性、2D/3D、展示预设、原图与校尺入口；回归构建、模式隔离与截图桥。具体截图及尺寸记录保存在忽略的本地QA目录。

实际验收：同一1543×892窗口，外层画布从742×531增长至1013×772，左栏x=0、右栏终点x=1543；专注模式画布宽1543，切换保持当前3D。住宅、Tugendhat和办公的已有参考方案均实际载入3D；家具库、属性浮层可打开关闭，工作室/日光切换实际改变光照。浏览器错误/警告日志为空。

本轮19项引擎回归（含三例旧JSON与capture恢复）、17项前端交互回归和1项真实Chromium布局测试通过；布局分别测1440×900、1920×1080、390×844。类型检查、lab构建及public/admin/lab内存隔离检查通过。既有30个项目及15个已保存方案的导出哈希在验收前后相同，未创建新模型任务。
