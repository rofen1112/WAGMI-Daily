# AI Lab local API

Start from the isolated checkout with `powershell -File scripts/start-ai-lab-api.ps1` (Python 3.13, standard library only). The server binds exclusively to `127.0.0.1:8786`. Vite must proxy `/api/ai-lab/v1` and `/viewer-assets` to that port. It does not serve the checkout root, private config, SQLite, arbitrary files, or legacy case directories.

The designated private file is `.env.ai-lab.local` in the checkout root. Preferred keys:

```dotenv
AI_LAB_API_KEY=YOUR_PRIVATE_KEY
AI_LAB_GATEWAY_WIRE_MODE=responses
AI_LAB_GATEWAY_IMAGE_VERIFIED=0
AI_LAB_MODEL_TIMEOUT=90
AI_LAB_MAX_OUTPUT_TOKENS=12000
# Optional: leave absent to preserve the gateway's existing default.
# AI_LAB_REASONING_EFFORT=none
AI_LAB_JSON_MODE=0
AI_LAB_WORKFLOW_MAX_CALLS=8
AI_LAB_WORKFLOW_MAX_REPAIRS=2
AI_LAB_WORKFLOW_MAX_REVIEWS=2
```

Root verified Responses text and image input on this gateway. The backend's separate image gate must still be set explicitly to `1` after evidence exists for the deployment. Default wire mode remains the originally documented `messages` shape; use `responses` for the verified protocol. No automatic cross-protocol or network retries occur. Requests go only to `https://etc.seedance-api.net/server/api/call`, model `deepseek-v4-1-flash-260910`. Keys are backend-only. A worker can make one generation call and at most one targeted geometry repair call; every provided usage value is recorded per call, absent usage and monetary cost remain null. Timeout is bounded to 5..180 seconds per call. A cancelled in-flight request may still incur vendor fees, but cannot commit a scene.

Optional `AI_LAB_REASONING_EFFORT=none|low|high|max` sends `reasoning:{effort:...}` only in Responses mode. An absent/empty option sends no new parameter; invalid values fail before network access. `none` has now been tested on this gateway with actual zero reasoning-token usage. This proves the parameter's effect for those requests, not scene quality. This option does not send `thinking`, change output limits, or add a retry. See [reasoning-notes.md](reasoning-notes.md) for the original evidence and bounded verification plan, and [model validation](../../docs/ai-lab-model-validation.md) for actual outcomes.

Optional `AI_LAB_JSON_MODE=0|1` defaults to `0` and sends no format parameter while disabled. Setting `1` is allowed only with Responses mode and sends `text:{format:{type:'json_object'}}`; invalid values or a wrong protocol fail before network access. The root verified both text and image-plus-JSON-object probes on the actual gateway. Workflow job/checkpoint/call settings record `jsonMode`. The mode is a syntax aid: strict standard JSON parsing and all scale/geometry/visual checks still apply, with no eval, JSON5, permissive fallback or extra retry.

With JSON mode enabled, provider normalization `strict-json-repeat-v1` can collapse repeated complete JSON objects only after every object in every nonblank output-text part has been strictly decoded and proven byte-identical or structurally identical. Exact decimal-number comparison distinguishes true from 1 and preserves numeric precision; duplicate keys, NaN/Infinity, different objects, incomplete parts, prefaces and trailing text are rejected. Partial parts are never stitched into a new JSON object. A single object keeps its original text. The limit is 64 objects; exceeding it fails rather than silently dropping later content. JSON mode 0 keeps legacy text/concatenation behavior unchanged, and request protocol/settings are not silently changed.

Provider responses and new workflow call audits record `normalization:{version,applied,count,textPartCount,equivalence,reason}`. A disabled mode has an unknown count rather than a guessed count. Private stage artifacts additionally record `outputStructure` with allowlisted item/part types, counts, text hashes and lengths; this distinguishes future gateway output-block aggregation from a duplicated object inside one block without storing an entire raw wire envelope. Rejected responses retain supplied usage and private shape metadata. Public call audits contain no raw output text, provider Key or filesystem path. The regression fixture is an abstract analysis object, not a private plan or image.

The current generation prompt version is `pixel-scene-v2`, defined by `PROMPT_VERSION` in `prompts.py` and exposed by health/job records. It makes original pixel bounds, polygon vertices, optional window-height arrays and compiled-mm repair diagnostics explicit. Historical `pixel-scene-v1` benchmark rows describe earlier tests; that version is not the current generation prompt. A prompt version and a successful geometry check do not constitute visual-quality acceptance.

## Staged generation workflow

Payloads without `pipelineVersion` keep `legacy-single-v1` for reproducible comparison. The new UI explicitly submits `pipelineVersion:'codex-workflow-v1'`; its current prompt version is `codex-workflow-prompts-v3`, which requires strictly valid double-quoted JSON in every stage and describes second-look scale output with a standard JSON Schema. Version `v2` introduced the bounded second-look scale-estimation stage; earlier `v1` synthetic/full-workflow runs did not include it. Historical runs retain their labels. Legacy generation continues using `pixel-scene-v2`. A legacy result must not be described as having passed the staged workflow.

New generation performs image analysis, pixel architecture, visible furniture/fixed facilities, scene and editor-state validation, private draft capture, model visual review, and only then optimistic scene commit. Explicit wall centerlines, repeated furniture rows and stair runs are expanded deterministically before repair diagnostics; no source case coordinates or baseline JSON go to the model. The default budget is 8 actual/reserved provider requests, at most 2 repair calls shared across geometry and visual repairs, and at most 2 visual reviews. There are no protocol retries. Provider settings, input/output hashes, private stage outputs, original-pixel candidates, compiled scenes, checks, supplied usage and timing are retained under the private data directory even on failure.

Private budget configuration accepts `AI_LAB_WORKFLOW_MAX_CALLS` from 4..16, `AI_LAB_WORKFLOW_MAX_REPAIRS` from 0..6, and `AI_LAB_WORKFLOW_MAX_REVIEWS` from 1..6. The total cap must cover 3 basic calls plus the configured repair and review caps. Invalid values/combinations explicitly fail startup; they are never clamped. For example `12/4/4` is a bounded migration-QA configuration, not a statement about model quality. Health advertises the current limits for new tasks. Each new job snapshots its limits at creation and persists them in its private checkpoint; `job.budget` always reports that snapshot. Restart or environment changes do not enlarge an existing job's budget. Older checkpoints or queued payloads without limits retain historical `8/2/2`. Expanded budgets never relax visual or geometry checks and do not trigger a protocol/network retry.

Use `scaleMode:'auto'` without a scale, `manual` with positive `mmPerPixel`, or `calibrated` with `calibration:{p1:[originalX,originalY],p2:[originalX,originalY],lengthMm:number}`. All modes still run image analysis. Manual/calibrated input overrides automatic scale. The service computes annotation-anchor ratios itself and requires them to agree within 2%; contradictory annotations require input rather than falling back to a familiar example's scale. Without annotations, the service also computes the median of `lengthMm / pixel distance` across object-prior anchors; a model-supplied `mmPerPixel` is optional and cannot override that calculation. The original reported range must cover every anchor ratio and the median; contradictory priors require input, with no range widening, evidence dropping or second-look substitution. Priors retain low/medium confidence and estimated status, never measured because a model claims so. Measured means calibrated to a supplied/read length, not site-verified accuracy.

The bounded analysis summary is published immediately, including when scale selection subsequently needs input. In auto mode only, if analysis has no dimension annotations and cannot provide a usable prior-based scale, one optional `scale_estimation` image call looks again at visible reference objects. It may return only a scale object with original-pixel endpoints, openly assumed typical lengths, a range and low confidence; it requests at least two independent references when clearly visible. It cannot invent dimension annotations or user measurements, alter geometry, use a baseline's scale, or bypass the existing scale checks. The checkpoint records that the second look has been used, and all supplied usage/time counts against the same fixed job budget. If the single second look still fails, the job needs input. Manual/calibrated jobs do not make this extra call, and conflicting dimension annotations never downgrade to object-prior estimates.

A valid uncommitted draft has `status:'awaiting_review_images'`, `stage:'preview'`, `draft:{id,viewerUrl}`, and `reviewImagesRequired:true`. This persisted checkpoint releases the single worker so other projects continue. `GET /jobs/:id/draft` returns the valid scene/state/scale/source image for that draft. `GET /jobs/:id/viewer?draftId=...` renders it with a separate draft storage scope. A private draft does not increment the project's committed version.

The actual same-origin viewer captures SVG 2D and Three.js 3D in the browser; no headless browser or Codex screenshot service is used. Submit both with `POST /jobs/:id/review-images {draftId,images:[{view:'2d',dataUrl},{view:'3d',dataUrl}]}`. Accepted captures are PNG/JPEG/WebP, up to 1280 pixels per side and 4MB each. Identical captures for the current draft are idempotent; stale draft IDs and conflicting replacements return 409. New repaired candidates get new draft IDs and require fresh captures. Captures do not include the original-image overlay. The original image and both actual captures are sent together for structured visual review; public `visualReview` has `pass`, `issues`, `limitations`, `reasons`, `reason` and `acceptance:'model_review_only'`. Critical/major issues override a claimed pass, and reports beyond the bounded issue limit are rejected instead of silently hiding later issues.

Waiting checkpoints survive restart without replay. A request interrupted while running fails and retains unknown vendor usage rather than being automatically repeated. Cancellation prevents later model calls and scene commit; an already sent request may still be charged. The model's visual pass is not independent human benchmark acceptance. Offline tests exercise orchestration and safety, not real reconstruction quality.

Private data lives in `.local-ai-lab/{lab.sqlite3,assets/,baselines/}`. Each baseline is a private `baselines/<opaque-id>.json` containing `{title,scene,state?,sourceAsset?}`. Baseline IDs come from filenames, never external paths. Reference loading is explicitly stored as `baseline_reference`; chat edits retain that provenance as `baseline_reference_modified`, including subsequent edits and state saves. Actual model output is `generated`, and edits to generated scenes are `modified`.

Jobs expose `queued`, `running`, `succeeded`, `failed`, `cancelled`, or `needs_input`, with progress 0..100. POST jobs accepts an `Idempotency-Key` header or body `idempotencyKey`; key reuse with a different body returns 409. `baseVersion` enforces optimistic concurrency, including the final worker commit. On restart, queued work resumes and previously running work fails as interrupted; paid calls are not silently replayed.

Generation jobs also expose `sourceAsset:{id,name,mime,width,height,url}` and `input:{scaleMode?,mmPerPixel?,calibration?,prompt?}` so a failed/needs-input project can reopen its source and restore the user's scale/calibration/requirements without re-upload. New jobs record only the submitted, allowed fields; calibration exposes only its two pixel points and length. A read-only `public_job` adapter supplements historical records from existing payloads for both GET jobs and projects.latestJob, without rewriting old rows or inferring absent legacy fields. Internal payload fields, asset filenames, provider keys and paths are excluded. Modification jobs do not present these generation inputs. If an old source asset is unavailable, its public sourceAsset is null rather than an internal path.

An executed job always records `usage:{calls:[...],cost:null}`. An empty `calls` array explicitly means that task made no model call (for example a deterministic local edit); it does not estimate a zero monetary cost. Queued tasks, cancellation before execution, and historical unknown usage can remain null. Existing null records are not backfilled with guessed values.

The complete compiled legacy scene and separate renderer state are stored in every immutable version. Editor state has exactly `furniture`, `rooms`, `demolished`, `measures` and is checked by the engine. Saving editor state retains the full original scene, and chat modifications start from the latest editor furniture and room overrides. GET export includes both. No generated code is executed.

New workflow commits bind a service-controlled `scene.metadata.generation` audit record to the initial generated scene: pipeline/prompt versions, configured model, job ID, source SHA-256, whitelisted non-secret settings, fixed limits, and the normalized model visual review. Model-provided generation claims are stripped before draft rendering and overwritten by the service at commit; scene and editor state are checked again before saving. `reviewAppliesTo:'initial_generated_scene'` makes clear that subsequent manual/chat versions inherit the initial audit rather than gaining a new quality acceptance. Existing stored versions are not rewritten, and the editor-state structure is unchanged.

Current deterministic chat grammar (coordinates/sizes in mm): `把f1移动到1000,2000`, `f1旋转到90度`, `f1尺寸改为1200x600`, `r1改名为会议室`, `r1材质改为carpet`. Use unambiguous IDs, names, or furniture types. These exact forms work without a provider call. With a configured provider, other natural language (for example a relative move with an explicit distance) makes one text request to translate the instruction into the same restricted patch. The model receives current editable object properties, and cannot add/remove objects or modify geometry. Missing values, unsupported edits and ambiguity return `needs_input`; every model patch must pass the same engine validation and version transaction. Modification makes no repair call. Clients can also send `patch:{operations:[{op:'update_furniture',id:'f1',changes:{cx:1000}}]}` or `update_room` with `name`/`mat`. This is bounded conversational attribute editing, not general geometry editing.

Run `python tests/ai-lab-server.test.py` for legacy provider/persistence/cancellation/boundary regression checks, and `python tests/ai-lab-server-workflow.test.py` for the staged workflow with the actual deterministic engine and an injected provider. The latter covers wait/capture/review/repair/save, stale/idempotent captures, immediate-receipt concurrency, valid editor-state gating, scale provenance, worker release, budgets, cancellation, optimistic conflicts and restart behavior. Local API has no user authentication or multi-user isolation and is not a public deployment.
